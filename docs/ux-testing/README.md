# UX-тестирование Awaisa

Набор для проверки, насколько удобно пользоваться сайтом трём группам людей: старшему
поколению (в том числе со слабым зрением), людям среднего возраста и молодым (в основном с
телефона). Четвёртая персона — владелец салона.

| Что | Где |
|---|---|
| Персоны и их задачи | [personas.md](personas.md), в коде — [`tests/ux/personas.ts`](../../tests/ux/personas.ts) |
| Автоматические проверки | [`tests/ux/`](../../tests/ux) |
| Отчёт | `reports/ux/index.html` (создаётся прогоном, в git не попадает) |
| Живые сессии | [moderator-script.md](moderator-script.md), [observation-sheet.md](observation-sheet.md), [sus-questionnaire.md](sus-questionnaire.md), [recruiting.md](recruiting.md) |
| Аналитика (предложение) | [analytics-proposal.md](analytics-proposal.md) |

## Запуск

Нужны Docker и демо-данные (один раз):

```bash
pnpm db:up
```

```bash
pnpm db:seed
```

Затем из корня:

```bash
pnpm test:ux
```

Все персоны, все устройства, все сценарии, около 60 прогонов. Кит сам собирает и поднимает
API на :4310 и веб на :3310 (production-сборка в `apps/web/.next-ux`, `apps/api/dist-ux`), так
что dev-серверы и e2e не мешают. Первый запуск дольше на время сборки.

```bash
pnpm test:a11y
```

Только доступность: axe (WCAG 2.2 AA), размер целей, ошибки форм и проход с клавиатуры, по
одному устройству на персону.

```bash
pnpm test:ux:report
```

Пересобрать `reports/ux/index.html` из последних результатов и открыть его.

Отдельная персона или устройство:

```bash
pnpm --filter @awaisa/ux-tests exec playwright test --project 'senior·laptop-zoom-200'
```

Переменные окружения:

- `UX_WORKERS=1` — запускать тесты по одному (по умолчанию 2).
- `UX_CHECKS=axe,layout` — оставить только эти проверки.
- `UX_BASE_URL` и `UX_API_URL` — проверять уже запущенный стенд.

## Что проверяется

| Проверка | Для кого | Как |
|---|---|---|
| axe, WCAG 2.2 A/AA (контраст ≥ 4,5:1, подписи полей, alt, имена кнопок) | все | `@axe-core/playwright` на каждом шаге каждого сценария |
| Цели ≥ 44×44 (< 24 без отступа — нарушение 2.5.8) | все | размеры всех кнопок, ссылок, полей на экране |
| Только клавиатура, фокус виден и не под панелью (2.4.7, 2.4.11), фокус возвращается после Esc | ноутбук Сергея, ноутбук Галины при 200% | Tab / Shift+Tab / Enter / Space / стрелки / Esc |
| Масштаб 200%: нет прокрутки вбок, текст не обрезан, кнопки не перекрыты, панели не съедают экран | Галина | 1366×768 при 200% = 683×384 CSS px |
| Крупный шрифт 150% (как Android) | Галина | все `--text-*` токены × 1,5 |
| Симуляция зрения: размытие, сниженный контраст, протанопия, дейтеранопия, тританопия | Галина | CDP `Emulation.setEmulatedVisionDeficiency`, скриншот каждого шага в отчёте |
| Таймеры: сообщения и подсказки, которые исчезают сами; текст, меняющийся без действий | все, строже для Галины | наблюдение за live-регионами и DOM |
| Ошибки форм: есть текст, рядом с полем, `aria-invalid`, объявляются | все | неверный номер, неверный код, нет оценки, занятый адрес |
| Цена, длительность, адрес и условия видны до личных данных | Сергей | видимый текст до первого поля «Имя» / «Телефон» |
| Время до интерактивности и время сценария на Slow 4G и CPU × 4 | Айпери | CDP, бюджеты в `personas.ts` |
| Число действий и полей до цели | все | бюджеты в `personas.ts` |

Серьёзные и критичные находки делают тест красным, умеренные отмечаются как «Замечания».
Платежи — только встроенная тестовая касса (`PAYMENT_DRIVER=test`), вход — тестовый код
`111111`. Тестовые данные называются `E2E UX …` и удаляются после прогона.

## В CI

`.github/workflows/ux.yml`:

- на каждый PR, который трогает `apps/web`, `packages/ui`, `packages/tokens` или сам кит, — `pnpm test:a11y` (по одному устройству на персону);
- каждую ночь в 03:00 по Бишкеку и по кнопке «Run workflow» — весь кит (`pnpm test:ux`);
- отчёт `reports/ux` приложен к каждому прогону (артефакт `ux-report`, 14 дней), в том числе к упавшему.

Красным прогон делают только критичные и серьёзные находки. axe-находка «цель частично закрыта» считается умеренной: она зависит от того, куда прокручена страница. Настоящие перекрытия ловит своя проверка кита (`ux-control-covered`).

## Ручные находки

Проблемы, замеченные глазами (на живой сессии или при разборе отчёта), добавляются в
[`tests/ux/report/manual-findings.json`](../../tests/ux/report/manual-findings.json) со
скриншотом в `tests/ux/report/manual/`. В отчёте они стоят среди автоматических, по своему
приоритету, с пометкой «найдено вручную». Проверку под них писать не нужно.

## Ограничения

- Это автоматика: она не заменяет живые сессии, а подсказывает, куда смотреть.
- iPhone эмулируются в Chromium (размер, плотность, касания, user agent): симуляция зрения
  и сети есть только в Chrome DevTools. Особенности Safari так не видны.
- Крупный шрифт масштабирует токены типографики; размеры, заданные в компоненте числом, не
  растут (так в отчёт и попадают).
- Проверка видимого фокуса сравнивает пиксели вокруг элемента с фокусом и без.
- Время на Slow 4G зависит от машины; сравнивайте прогоны на одном компьютере.
